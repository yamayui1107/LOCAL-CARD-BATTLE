# 地域カードバトル（LOCAL CARD BATTLE）

日本の地名をカード化したHTMLベースのコレクション＆対戦ゲーム（DBなし・静的ファイルのみ）。

共通エンジン（`engine/`）＋このフォルダ（テーマ設定・データ・画像）の合成で動く。
モノレポ全体の構成・デプロイ・新テーマの作り方はリポジトリ直下の [README.md](../../README.md) を参照。

## 起動方法

**`ゲーム起動.bat` をダブルクリック**（サーバー起動＋ブラウザが自動で開く）。

`index.html`の直接ダブルクリック（`file://`）では動かない。ブラウザのセキュリティ制約で
CSVの`fetch`とES Modulesの読み込みがブロックされ、真っ白になる。

手動で起動する場合（リポジトリ直下で）:

```
node scripts/serve.mjs battle 8000
```

→ http://localhost:8000 を開く

## 公開（Vercel）

このゲームのVercelプロジェクト設定（詳細はリポジトリ直下のREADME参照）:

- Build Command: `node scripts/build.mjs battle` / Output Directory: `dist`
- `vercel.json`（リポジトリ直下・全ゲーム共有）: 画像に長期キャッシュ、CSVにContent-Typeを付与
- 配信されるのは engine + このフォルダの合成結果（`tools/`・`__*.html`・batは除外、約84MB）
- ゲーム実行中の外部通信は自動生成カードのWikimedia画像のみ。サーバー処理・DBは不要

## 構成（このフォルダ = ゲーム固有部分）

```
index.html        画面（テーマ文言はconfig.jsから流し込まれる。head/OGPはこのゲーム専用）
js/config.js      ★ゲームテーマ設定（タイトル・地元確変・地方分類・文言・CSV列名・広告/GA ID）
about.html ほか   静的ページ・ads.txt

data/  ※正規化されたマスタ群
  card_master.csv    カード本体: id,name,reading,type,<グループ列>,rarity
                     （グループ列の列名はconfig.jsのGROUP.csvFieldで指定。本作はprefecture）
  card_detail.csv    カード詳細: card_id,attack,defense,description
  card_tag.csv       カード⇔タグ関連: card_id,tag（1行1タグ）
  tag_master.csv     タグ定義: tag,description
  synergy_master.csv シナジー定義: id,name,tag,count,multiplier,description

tools/             カードデータの自動生成スクリプト（地名テーマ専用）
```

エンジン側（画面制御・ガチャ・対戦・セーブ）は `engine/js/` にあり全ゲーム共通。

セーブデータの互換: 旧フィールド `homePref` は `favorite` に自動移行される（engine/js/state.jsのload参照）。

## ゲーム仕様

- **カード**: 都道府県(UR 47枚) / **全市区町村(1,741枚)** / 名所(27枚) = **全1,815枚**
  - 手書きキュレーション301枚 + 自動生成1,514枚（有名度=Wikipediaページビューから攻撃力・レアリティを自動算出、豆知識はWikipedia冒頭文）
- **ガチャ**: 1パック5枚・スタミナ2消費。基礎排出率 N59/R28/SR10/SSR2.4/UR0.6（実効 SSR約3.5%・UR約0.8%）。
  **5パック（25枚）ごとに1枚SR以上確定**（パック画面に「あと○パック」カウンター表示）。パック末尾はR以上確定。20パックSSR以上なしで天井
- **地元確変**: 地元都道府県のカードは排出重み×2.5。ヘッダーの地元バッジからいつでも変更可（コレクションは維持）
- **スタミナ**: 自然回復の上限10、2分で1回復。広告視聴で+10・回数無制限、上限を超えて30まで貯め込める
- **シナジー**: 同タグ規定枚数で発動、該当シナジーは全て乗算スタック（青天井）。タグ38種・シナジー40種
- **画像**: 手書き301枚はローカル保存、自動生成分はWikimediaサムネイルの実行時読み込み（lazy load・図鑑は120枚ずつ段階表示）
  - 一覧では240pxサムネイル（ローカル分は`images/thumb/`、`cd tools && node make_thumbs.mjs`で生成）、拡大表示のみフル解像度

## カードの一括追加（自動パイプライン）

```
node tools/add_municipalities.mjs        # 全市区町村を追加（済み）
node tools/add_municipalities.mjs --dry  # 件数確認のみ
```

Wikipedia照会・ページビュー・画像URLは `tools/cache/muni_cache.json` にキャッシュされ、再実行は取得済みをスキップする。面白い自治体の手動調整はスクリプト内 `OVERRIDES` に追記。

## カードの追加手順

1. `card_master.csv` に1行追加（idは `C228` のように既存の連番に続ける）
   - `type`: `pref`(都道府県) / `city`(市区町村) / `spot`(名所)
2. `card_detail.csv` に同じ `card_id` で攻/防と豆知識を1行追加
3. `card_tag.csv` にタグを付けたい数だけ行を追加（例: `C228,温泉地`）
   - 新しいタグを作る場合は先に `tag_master.csv` に定義を追加
4. 新タグでシナジーを作るなら `synergy_master.csv` に1行追加

詳細行の欠落や未定義タグはロード時にブラウザのコンソールへ警告が出る。

## カード画像の一括取得

Wikipedia(ja)の各記事の代表画像をAPIで一括取得できる。

```
node tools/fetch_images.mjs               # SSR/URのみ（デフォルト）
node tools/fetch_images.mjs --rarity=all  # 全カード
```

- 全301枚取得済み（約80MB）。`images/<card_id>.jpg` に保存され、`data/card_image.csv`（画像マスタ）に出典・ライセンス・作者が自動記録される
- APIを叩くのはこのツール実行時だけ。ゲーム実行中の外部通信はゼロ
- 画像マスタに行があるカードだけ、ゲーム内で写真背景になる（無いカードは従来デザイン）
- カード名と記事名が違う場合はスクリプト内 `TITLE_OVERRIDES` に追記して再実行（取得済みはスキップされる）
- 画像はCC BY-SA等のライセンス。ゲーム内のカード詳細に出典表記を表示している。公開時はこの表記を残すこと

## 対戦ルール（Ph2・一発勝負方式）

- 事前に組んだデッキ5枚同士の一発勝負（オートバトル）
- **戦闘力 = Σ(攻撃 × シナジー倍率) + Σ防御 × 0.4**。高い方が勝ち
- シナジーはデッキ内の同タグ枚数で発動。**カードが該当する発動中シナジーは全て乗算でスタックする**（青天井仕様。京都市で古都×世界遺産×政令指定都市×県庁所在地×新幹線を全部盛ると1枚で20倍超も可能）
- 対戦画面ではシナジーが1つずつバナー演出で発動し、該当カードが光る
- おまかせ編成は山登り法でシナジー込み戦闘力を直接最大化。編成画面ではデッキ内カードに適用倍率バッジ、プールに「追加時の戦闘力上昇値」バッジ（上昇値順ソート）とタグ絞り込みが付く
- CPUデッキは多様な候補から「プレイヤー戦闘力に僅差で届かない候補」を58%、「僅差で上回る候補」を42%で採用（`js/battle.js`のPLAYER_WIN_RATE）。毎回接戦になり、長期勝率は55〜62%に収束することをシミュレーションで確認済み
- デッキ編成画面に戦闘力・発動シナジー・「あと1枚」リーチを常時表示
- **CPU戦・フレンド戦にチケット報酬は無い**。スタミナを消費せず無限に回せるため、報酬を付けると
  放置周回でチケットが無限に湧き、ガチャ経済と広告視聴の動機が両方壊れる（連勝リワードは廃止済み）。
  連勝数は戦績・自慢用の数字としてのみ残している

### 全国制覇モード（固定ボス47体）

- 北海道→沖縄の順に「◯◯の主」が待ち受ける。戦闘力は12,020から幾何級数で上昇し、
  最終ボス「沖縄の主」は1,135,970（理論最強値1,266,596の約90%）
- おまかせ編成の到達上限は約67万＝41体目まで。**ラスト6体は手動での最適構築が必須**
- **チケットの入手経路はここだけ**。初撃破の節目のみ配布し、5体ごと+2、47体制覇でさらに+5＝生涯23枚。
  ボスデッキは`data/boss_master.csv`、再生成は `node tools/build_bosses.mjs`
- ランダムCPU戦（対戦開始ボタン）はフリー対戦として共存（報酬なし）

## チケット・スタミナ経済

| 入手 | 量 | 上限 |
|---|---|---|
| 全国制覇のボス初撃破 | 5体ごと+2、47体で+5 | 生涯23枚 |
| 初回シェア（`sharedOnce`） | +30枚 | 1回のみ |
| CPU戦・フレンド戦 | 0枚 | — |

- チケット1枚 = パック1回（スタミナ2の代替）。消費は`useTicket()`のみ
- シェアは実際に投稿されたか検証できない（intent URLもWeb Share APIも結果を返さない）ため、
  **報酬は必ず一度きりに固定する**。繰り返し配ると「Xボタンを押して閉じるだけ」の無限チケット源になる
- スタミナ: 自然回復の上限10（2分/1）。**広告視聴は+10で、上限10を超えて30まで貯まる**（`STAMINA_CAP`）。
  満タン時に広告ボタンが押せないと動線が死ぬための仕様で、上限超過中は自然回復が止まる

### 広告の動線（`js/ads.js`）

| 種類 | 場所 | 報酬 |
|---|---|---|
| リワード | パックタブ `#ad-btn` | スタミナ+10 |
| リワード | 開封結果 `#result-ad-btn`（スタミナ切れ時） | スタミナ+10 |
| リワード | 対戦結果 `#battle-ad-btn`（上限未満なら常時） | スタミナ+10 |
| インタースティシャル | 開封を閉じた時 / 対戦を閉じた時（3分クールダウン） | — |
| ディスプレイバナー | ヘッダー下・フッター上（`.ad-banner`） | — |

- 本番リリース前に `AD_TEST_MODE = false` にする（現在テスト広告）
- バナーは `AD_SLOT_BANNER` が空だと枠ごと描画されない。AdSense管理画面でディスプレイ広告ユニットを
  作成し、`data-ad-slot` の数字を貼ること

### フレンド対戦（デッキコード）

- 自分のデッキは `P13-C128-S01-C045-C206` 形式のコードで共有できる（対戦タブ下部）
- 相手のコードを貼り付ければサーバーなしで非同期対戦が成立する
